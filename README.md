# 逐帧 · Flipbook Studio

图像领域的新项目：像素动画与游戏精灵素材制作工作台。围绕“绘制像素 → 图层合成 → 动画时间轴 → 精灵图集与瓦片素材导出”设计。与已有PaperFlow扫描/OCR及ParticleScope颗粒定量分析不同；没有复用它们的业务处理模块。

要求落实：自有后台有效代码超过5000行，超过10组可操作功能，并提供实际构建、启动、健康检查和重启持久化验证的Docker Compose项目。逐文件代码量及SHA256见 `docs/line-count.json`，功能入口与操作见 `docs/功能与页面验收.txt`。

## Docker运行（推荐）

在本目录执行：

```bash
docker compose up -d --build
```

打开 http://127.0.0.1:8895 。首次构建需要下载Python基础镜像、字体和固定版本依赖，核心编辑及导出无需外部服务、账号、密钥、GPU或模型。

```bash
docker compose ps
docker compose logs --tail 100
docker compose restart
docker compose down
```

默认仅映射127.0.0.1。端口冲突时：`FLIPBOOK_PORT=8896 docker compose up -d --build`。PowerShell先执行 `$env:FLIPBOOK_PORT='8896'` 再启动。容器内部监听0.0.0.0是端口映射所需。

数据位于Docker命名卷 `solo5_flipbook-data`，容器内路径 `/app/data`。停止、删除或重建容器不删除命名卷；不要执行 `docker compose down -v`，除非确实要清空数据。镜像以UID10001普通用户运行，禁用额外capabilities，包含HTTP健康检查。Windows/macOS可使用相同Compose文件；本次实测环境是Linux amd64，未在Windows或Apple芯片真机验证。

备份可用页面“可编辑项目归档”导出当前项目（含当前图层、帧、片段、调色板、地图，不含历史和命名版本）。要完整备份全部历史，请停止容器后备份Docker命名卷；不要在服务运行时覆盖卷文件。

## 本机运行

需要Python3.12+：

```bash
bash start.sh
```

Windows安装Python3.12后双击 `start.bat`。Ctrl+C停止服务。`PORT`可指定端口；`FLIPBOOK_DATA_DIR`可指定数据目录，默认项目data。不要让本机服务与容器指向同一个正在写入的目录。脚本按requirements哈希更新虚拟环境依赖。Windows脚本未在Windows实机验证。

## 快速体验

1. 顶部选择“机器人行走”，点“打开演示”；得到12帧原创合成动画，64×64，总时长1080ms。
2. 点“播放”，可按逐帧时长播放；暂停后在画布点击或拖动铅笔，单笔写入后台并可撤销/重做。
3. 勾选时间轴帧后进入“动画工具箱”，可重定时、补间、减色、残影、透明遮罩、画布操作等；未勾选时工具默认作用于全部帧，面板会提示作用范围。
4. 右侧可添加图层、设置混合模式、透明度和变换。已有变换时，绘制前先“烘焙变换”。
5. “导出作品”选择APNG、GIF、WebP、图集或项目ZIP，创建任务后等待“可下载”。导出任务绑定创建时的源修订。
6. 打开“地形瓦片”演示，进入“瓦片地图”，创建地图后用棋盘填充或点格子绘制，下载地图和瓦片PNG包。

## 功能组（29组）

1. 动画项目创建、搜索、标签、说明、复制及可恢复归档。
2. PNG/APNG/GIF/WebP导入，保留动画帧和帧时长；多图追加或图层导入。
3. 原创机器人、火焰、星能球和地形瓦片演示。
4. 铅笔、橡皮、直线、矩形、椭圆、多边形、油漆桶、渐变和文字绘制。
5. 水平/垂直镜像笔刷、吸管、共享颜色与像素网格。
6. 矩形选区复制/移动，以及将合成帧用作图像印章。
7. 多图层增删、复制、排序、锁定、透明度、八种混合模式和图层合并。
8. 图层位置、旋转、缩放、翻转、变换烘焙与跨帧传播。
9. 帧时间轴、可变时长播放、前后帧、帧复制、重排和批量移除。
10. FPS/统一时长/按比例/指定总时长重定时、反转、往返展开和重复画面合并。
11. 动画片段、播放方向与循环次数。
12. 红蓝洋葱皮预览、网格和整数缩放。
13. 关键帧位置/缩放/旋转/透明度补间及八种缓动。
14. 预乘Alpha交叉过渡、贝塞尔路径和浮动/脉动/旋转等循环动画。
15. 打字字幕、放射爆发特效、运动残影和帧间透明平均。
16. 共享调色板提取、颜色清单、RGB/HSV渐变、颜色循环及三种减色/抖动策略。
17. 减色、描边、投影、Gamma、色相、透明区颜色外溢等像素效果及原子批量效果链。
18. 可复用像素效果配方的保存、应用、导入和导出。
19. 色键去背景、颜色通道Alpha、帧遮罩和透明度细修。
20. 统一画布缩放、扩边、裁切、透明并集裁边、旋转和内容对齐。
21. 保留边框的九宫格缩放与瓦片边缘融合。
22. 规则精灵表切片和透明沟槽/连通组件自动拆片。
23. 紧凑图集打包、旋转、透明裁边、间隔、边缘外扩、多页打包及图集还原。
24. 帧枢轴、碰撞框、自动Alpha碰撞框、像素碰撞预览和元数据导出。
25. 多层瓦片地图、瓦片翻转、格子绘制、棋盘/随机/边框填充及地图素材包。
26. 撤销/重做、命名版本、恢复、项目分支与版本结构差异。
27. 动画质量、重复帧、透明覆盖、帧间运动、首尾差异、接缝、摄影表、联系表与制作报告。
28. 异步GIF/APNG/WebP、PNG序列、图集、调色板及可编辑项目ZIP导出，取消、失败重试及重启中断状态。
29. 动作状态机工作区：把动画片段接成循环或一次性状态，配置输入事件、带优先级与暂存窗口的切换条件、不可打断区间和一次性动作回退；页面按键试演按虚拟毫秒时钟与真实帧曝光推进，实时记录每次切换/阻止/暂存过期/回退理由，同刻多条件按优先级和存储顺序确定性裁决，配置保存到项目，重开后继续试演，录制脚本可交后台确定性复算。不含地图或战斗数值。

这些功能有页面入口；部分高级参数通过JSON字段输入。功能组按完整业务能力归纳，不把加载动画、按钮或空白页算作独立功能。

## 数据、计算与边界

`projects/<id>/project.json`保存帧、图层、变换、时长、片段、调色板、地图和撤销链。图层像素以内容哈希保存为不可变PNG，修改不覆盖历史像素。每次项目编辑先在内存副本完成并校验，再原子提交项目JSON；失败的操作不提交项目修订，可能保留未引用的新素材文件。历史及命名版本引用素材，因此不会自动清理这些文件。

只允许一个服务进程写同一数据目录。线程锁处理进程内并发，并通过修订号拒绝过期写入；不支持多进程共享写入。撤销和恢复会增加修订号，不重用旧修订。导出以创建时的项目快照与不可变素材为准；取消在当前编码阶段结束后丢弃输出，不强制终止编码。重启把运行中任务标为interrupted，已完成文件仍可下载，重试使用当前项目。

图层从下向上合成，混合采用非预乘输入和预乘Alpha合成公式；跨帧插值采用预乘Alpha，减少透明色边。图集元数据记录源画布、裁边偏移、顺时针旋转、枢轴、碰撞框和帧时长。恢复图集时按元数据还原，不把紧凑排列误当作完整画布。

GIF为二值透明且最多255种可见颜色，帧时长量化到10ms，编码器可能合并相邻相同帧并累加时长；APNG保留完整Alpha。网页播放为预览，大画布/多图层时解码速度可能导致卡顿，正式输出请使用编码后的文件。

画布8–2048像素，每项目最多300帧、每帧16层，所有图层合计不超过4000万画布像素。单次请求体64MB，多图导入最多30个文件；内存编码限制为6000万输出像素。单页图集最大4096²；多页最多32页、总计6400万像素。组件切片和误差扩散抖动限100万像素。地图最多20张，每图最多8层，地图渲染限1600万像素。最多100个命名版本和100步可撤销历史；像素文件仍保留。

几何操作会先烘焙图层变换；缩放/裁切更新坐标元数据并清除旧地图，旋转会清空需重新绘制的碰撞框。移除帧若仍被地图作为瓦片引用，会拒绝，需先移除地图或调整结构。自动切片可能把不相连部件分开，需人工检查。色键/边缘融合也不保证任意素材达到预期质量。

地图包包含Tiled风格的地图JSON和独立PNG瓦片，本次未在外部关卡编辑器中导入验证；不要把生成格式等同于所有引擎兼容。项目不是游戏运行引擎，也不含OCR或科学颗粒测量业务。

## 编辑工作流扩展

工作台包含完整排版字体选择的打字字幕、可展开混合图层组合、共用原画、颜色角色墨水、带实例相位的动态地图和分轨镜头工作区。演示与可编辑项目素材位于 examples，可从“导入素材 → 恢复项目ZIP”打开。

分轨镜头最多4轨、30秒、300次曝光；源动画需同尺寸，轨道可以选择片段、起始时间、有限或持续循环、结束后停留或消失。共用原画仅在同一项目中共享像素，实例变换保持独立，其他像素特效可先脱离。颜色角色图层需要普通像素处理时可明确转为普通层。动态地图使用无限循环片段，页面可对照实时地图与资源播放。

组合层可展开并对内部图层作属性编辑，普通层仍可直接绘制。字幕可选 Noto 或 DejaVu 字体，需要依赖中列出的文字排版库和系统字体；Dockerfile包含相应系统依赖。

“图集工程”可以保存带固定UV槽位的版本，每个图块可预留后续补画像素，页面可比较版本像素、槽位与原画采样区域，并下载每个独立版本。解除固定后允许重新排列，工程包含在可编辑项目归档中。

## 动作状态机工作区

顶部“动作状态机”标签打开。先在时间轴用“保存所选片段”建立待机、行走、攻击等片段（也可在工作区一键生成按片段名匹配的示例），再把片段接成状态：循环状态用于待机/行走，一次性状态用于攻击并必须指定结束后的回退状态。每个状态可设置进入后的不可打断毫秒区间；切换条件包含来源/目标状态、输入事件、按下或松开时机、优先级和输入暂存窗口。

试演使用与后台同一套虚拟毫秒时钟和逐帧曝光规则，不依赖真实帧率：不可打断区间内的输入被记录为“切换被阻止”并按暂存窗口保留，窗口外确定性丢弃并记录“暂存过期”；一次性动作按真实曝光时间播完后自动回退；同一毫秒多个条件命中时，优先级最高者生效，优先级相同则按条件存储顺序裁决，被压制的条件同样写入理由日志。页面可键盘或按钮试演、查看当前状态/帧/暂存队列与完整切换理由，并把录制脚本交后台复算核对，或下载脚本JSON。状态机随项目原子保存并参与结构校验，被状态引用的片段不允许删除；不包含地图、战斗或数值系统。
